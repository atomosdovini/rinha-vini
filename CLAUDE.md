# CLAUDE.md — rinha-vini

Project guidance for future Claude Code sessions. Read PLAN.md alongside this file.

## What this project is

A submission for **Rinha de Backend 2026** — a fraud-detection API built on **vector search** under hard constraints (1 CPU, 350 MB RAM, ≥1 LB + 2 API replicas, port 9999, bridge network, public images). Scoring is `score_p99 + score_det`, range [-6000, +6000]. The official repo (read-only reference) lives at `~/rinha-de-backend-2026`.

This is **not** a CRUD backend. Treat it as a **specialized in-memory vector-search inference engine** that happens to speak HTTP. Optimize like an HFT/storage engine, not like an enterprise service.

## Core problem

For each `POST /fraud-score`:
1. Parse ~400 B JSON.
2. Compute a 14-dim vector via fixed normalization (see `~/rinha-de-backend-2026/docs/en/DETECTION_RULES.md`).
3. Find 5 nearest neighbors (Euclidean) among **3 M labeled vectors** from `resources/references.json.gz`.
4. Return `{approved: frauds_in_top5 < 3, fraud_score: frauds_in_top5/5}`.

Labels were generated by exact brute-force KNN — high recall matters.

## Hard constraints

| Item | Value |
|---|---|
| CPU total | 1.0 across all services |
| RAM total | 350 MB across all services |
| Topology | ≥1 LB (no business logic) + ≥2 APIs, round-robin |
| Port | 9999 on the LB |
| Network | `bridge` only (no host, no privileged) |
| Image | linux/amd64, public registry |
| Test host | Mac Mini Late 2014 (Haswell, AVX2 yes, AVX-512 no) |

## Scoring intuition (committed to memory)

- `score_p99`: +3000 at p99 ≤ 1 ms, -3000 at p99 > 2000 ms, +1000 per 10× improvement in between.
- `score_det`: rate term `1000·log10(1/ε)` minus `300·log10(1+E)`; cutoff to -3000 if `(FP+FN+Err)/N > 15%`.
- Error weights in `E`: FP=1, FN=3, Err=5. **Never return HTTP 500** — fall back to `{approved:true, fraud_score:0.0}`.

## Architecture decision (current)

**IVF (k-means) + int8 SIMD scan, mmap-shared between replicas.** See PLAN.md §5–10. Rejected: HNSW (too much RAM, cache-hostile), full brute force (memory-bandwidth-bound), KD-tree (degenerates at d=14).

Stack default: **Rust + monoio/hyper, single-threaded per replica, haproxy LB**. Zig is an acceptable alternative if hand-rolling more.

## Build pipeline (when implemented)

```
build-time (Dockerfile RUN):
  decompress references.json.gz → parse → k-means → quantize → emit /opt/index.bin
runtime:
  mmap /opt/index.bin (MAP_SHARED | MAP_POPULATE) → /ready 200 → serve
```

The index artifact is built **inside the image layer**, not at container start.

## Reference repo

`~/rinha-de-backend-2026/` is the official repo (do not modify). Key files:

- `docs/en/*.md` — full rules.
- `resources/references.json.gz` — the 3 M-vector dataset (~16 MB gz / 284 MB raw).
- `resources/mcc_risk.json`, `resources/normalization.json` — constants.
- `test/test.js` — k6 load test (ramping arrival 1→900 req/s over 120 s).
- `test/test-data.json` — labeled smoke/ramp payloads. **Do not memoize by `id`** — final test uses different payloads. Use only for offline recall validation.
- `config.json` — `max_cpu=1.0`, `max_memory_mb=350`, health endpoint `http://localhost:9999/ready`.

## Working conventions

- **Measure before optimizing.** Microbench each layer (parser, kernel, HTTP) before tuning. PLAN.md §21 has the per-component budget.
- **No allocation in the hot path.** Verify with heaptrack.
- **No frameworks in the hot path.** Hand-rolled JSON + LUT response is the goal.
- **Recall harness gates every build.** Compare against exact brute force on a held-out sample; require recall@5 ≥ 99.5 % and decision-agreement ≥ 99.7 %.
- **Phased rollout** (see PLAN.md §24). Resist the temptation to jump to phase 4 before phase 2 numbers are real.

## Things to never do

- Use a load balancer that inspects payloads (rules violation).
- Memoize answers by `id` (rules violation; final test changes payloads).
- Use the test payloads as a reference source (rules violation).
- Load `.json.gz` at container start.
- Use a general-purpose ANN library as a runtime dep.
- Return HTTP 500 from `/fraud-score` (massive scoring penalty; fall back to a deterministic safe answer).
- Use `host` networking or `privileged` mode (banned).
